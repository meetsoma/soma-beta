# Migration v0.42.0 → v0.42.1

## Doctor Actions

```json
{
  "settings-defaults": {},
  "settings-subkeys": {}
}
```

No settings keys added, removed, or renamed. No `applyOnceAlways` sentinel needed — every
change below is either purely additive (new optional template content that degrades to
nothing when absent) or a bugfix to code that was already silently non-functional (so there
is no prior "working" behavior for an upgrade to disrupt).

## Summary

Four `templates/default/` files changed this cycle — all additive, none renaming an existing
section or requiring action from an existing workspace.

### 1. `_boot.md` — last-session/last-reflection breadcrumb

Two new optional blocks (`{{#last_session_ref}}` / `{{#last_mlx_ref}}`) show a pointer to
the last session log / MLX reflection on disk, regardless of whether a preload was loaded.
Resolves to nothing on a project with no `memory/sessions/` or `memory/mlx/` yet — a fresh
`soma init` sees no change. An existing workspace with a customized `_boot.md` (workspace
copy wins over the shipped template) is unaffected unless the user re-syncs it by hand.

### 2. `DNA.md` — documents `_keepalives.md` and the memory slots

Pure documentation. `_keepalives.md` itself is still NOT shipped by default (opt-in,
unchanged from v0.42.0) — this only makes its existence discoverable in the file that
already explains the template system. No behavior change.

### 3. `_first-breath.md` — mentions `soma:*` tool calls alongside the CLI examples

Pure documentation addition (one paragraph). Only ever shown once, on a project's first-ever
session — has no effect on existing workspaces past their first boot.

### 4. `_child-template.md` — budget-scope clarification + `soma:agent.fold` mention

Documentation only: clarifies that `max-cost-usd` is really enforced only for
`claude-cli/*`-backed roles (see below), and points at `soma:agent.fold` for reviewing
accumulated knowledge. Does not change any existing role file — this is the scaffold
copied when *authoring a new* role, not applied to roles that already exist.

### 5. `max-cost-usd` enforcement bugfix (code, not a template) — was silently dead

Three compounding bugs meant a `claude-cli/*`-backed role's `max-cost-usd` was **never**
actually enforced, regardless of what the role declared (wrong frontmatter key read at the
enforcement site, plus two separate falsy-zero bugs that erased an explicit `0` into "no
cap"). Fixed in `core/delegate/run.ts` + `core/delegate/claude-cli.ts`.

**No migration action for existing roles.** A role that previously ran with an unenforced
(effectively unbounded) `max-cost-usd` now gets that number actually enforced. This is a
**behavior change**, not a breaking one: any role whose author set a realistic number will
simply start being held to it. The two roles this was originally investigated for
(`desktop-ui-artist`, `desktop-architect`, both `.soma/`-local project roles, not shipped)
explicitly want a `max-cost-usd: 0` hard cap on their free-tier/subscription backends — that
now actually works instead of silently doing nothing.

### 6. `soma:browser.render` `format:'markdown'` bugfix (code, not a template)

Was silently returning `document.body.innerText` (plain text, no HTML) instead of
`document.documentElement.outerHTML` whenever no `selector` was given — the documented
default usage of a v0.42.0 headline feature never actually converted anything. Fixed in
`extensions/soma-addons/browser.ts` + `extensions/soma-addons/_html2md.ts` (which also gained
anchor-aware nav/header/footer stripping so a page's own in-content `<header>` survives).

**No migration action.** Any caller relying on `format:'markdown'` without a selector was
already getting broken output; this fix makes it work as documented. A caller that was
somehow depending on the broken innerText-dump behavior (unlikely, since it silently claimed
`format:"markdown"` while returning unconverted text) will now get real markdown instead.
